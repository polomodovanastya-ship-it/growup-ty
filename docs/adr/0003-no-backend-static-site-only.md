# ADR-0003: Отказ от бэкенда (Supabase)

- **Статус:** Принят
- **Дата:** 2026-08-22
- **Заменяет часть:** [ADR-0002](./0002-migrate-from-lovable-to-github-pages-and-cursor.md) (пункты про Supabase)

## Контекст

Изначально сайт использовал **Supabase** для:

- сохранения результатов Kidscreen-теста;
- учёта кликов по mood-emoji;
- сохранения результатов career-квиза;
- админ-панели с авторизацией и аналитикой;
- очереди email через edge functions.

Для текущего этапа проекта бэкенд не нужен:

- сайт — информационный ресурс с клиентскими тестами;
- результаты тестов пользователь видит сразу на экране и может скачать PDF — **сохранять их на сервере не требуется**;
- админка и аналитика не используются;
- усложняет деплой (секреты, CORS, Supabase Dashboard).

Фронтенд уже деплоится как статика на GitHub Pages — логично убрать серверную зависимость полностью.

## Решение

**Отказываемся от Supabase и любого бэкенда. Сайт — полностью статический SPA.**

### Что остаётся клиентским

| Функция | Поведение |
|---------|-----------|
| Kidscreen-тест | Подсчёт, интерпретация, рекомендации, PDF — всё в браузере |
| Career-квиз | Результат показывается на экране, без сохранения |
| Mood check-in | Открывает тест, UTM-метки в URL — без отправки на сервер |

### Что убираем

- каталог `supabase/` (миграции, edge functions);
- `src/integrations/supabase/`;
- зависимость `@supabase/supabase-js`;
- страницы `/admin`, `/admin/login`, `/reset-password`;
- компонент `AdminDashboard`;
- GitHub Secrets `VITE_SUPABASE_*` из CI;
- настройку Supabase URL configuration из инструкции деплоя.

### Если понадобится бэкенд снова

Новое решение — отдельный ADR. Варианты: form-to-email, serverless function только для одной задачи, external analytics.

## Рассмотренные альтернативы

- **Оставить Supabase только для аналитики** — лишняя инфраструктура без явной потребности; отвергнуто.
- **Сохранять в localStorage** — не нужно: пользователь получает результат сразу и PDF; отвергнуто.
- **Formspare / Google Sheets** — возможны позже для обратной связи, но не для текущего scope.

## Последствия

### Плюсы

- Простой деплой: только статика, без секретов в CI.
- Нет расходов и обслуживания Supabase.
- Меньше surface area: нет auth, RLS, edge functions.
- Соответствие privacy-by-design: данные тестов не покидают браузер.

### Минусы

- Нет централизованной аналитики результатов тестов.
- Нет админ-панели для просмотра данных.
- Email-рассылки через Supabase queue больше не работают (не использовались на фронте).
